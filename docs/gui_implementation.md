# QUBO Validator Implementation Notes

## Architecture

The implementation splits pure QUBO parsing, optimization, visualization, and export logic from the PySide6 interface:

- `src/qubo_validator/analyzer.py`: AST-based formula and linear constraint parser, `dimod` / `dwave-samplers` execution, `z3` constraint satisfiability checks, Lagrangian penalty validation, Matplotlib figure generators, and ZIP export.
- `src/qubo_validator/gui.py`: Declares `GUI(QMainWindow)` using `PySide6` and `matplotlib.backends.backend_qtagg.FigureCanvasQTAgg`.
- `src/qubo_validator/qubo_validator.py`: Application entrypoint exposing `create_application()` and `main()` to instantiate `GUI` and run the Qt event loop.
- `src/qubo_validator/__init__.py`: Re-exports `GUI`.

## Dependency Alignment

Although `docs/specs/project_spec.md` mentions PyQt and SymPy in prose, `pyproject.toml` and `requirements.txt` ship `pyside6` and `z3-solver` (with `rustworkx` present in `.venv` and `networkx` in `uv.lock`):

- **Qt binding**: Implemented with `PySide6` (`QMainWindow`, `QStackedWidget`, `QScrollArea`, `QThread`).
- **Formula parsing**: Uses Python's `ast` module with an explicit node whitelist (`+`, `-`, `*`, `/`, `**`, `^` normalized to `**`, `=`, `==`, `<=`, `>=`, and chained inequalities) directly constructing `dimod.Binary` or `dimod.Spin` quadratic models without `sympy` or `eval()`.
- **Graph rendering**: Builds a `rustworkx.PyGraph` from the pure QUBO (excluding penalties) and renders via `rustworkx.visualization.mpl_draw`, falling back to `networkx` if `rustworkx` is unavailable.

## Key Behaviors

1. **Qubit Counting**:
   - Decision variables (`x*` or non-slack identifiers) in the QUBO formula are counted as `individual variables`.
   - Explicit slack identifiers (`s`, `s0`, `s_0`, `slack_*`) and binary-encoded slack variables generated by `dimod.BinaryQuadraticModel.add_linear_inequality_constraint` are counted in `total slack`.
   - Non-slack variables introduced only in the Penalties box are counted under `for penalties`.
   - `total = total_slack + individual_variables + for_penalties`.
2. **Energy Landscape Matrix**:
   - All $2^n$ bit-string energies (up to `MAX_EXACT_QUBITS = 14`) are evaluated vectorized via `bqm.energies()` and reshaped into a $2^{\lfloor n/2 \rfloor} \times 2^{\lceil n/2 \rceil}$ heatmap with lowest/highest markers on both axes and colorbar.
3. **Penalty Validation**:
   - Evaluates the pure QUBO `[min, max]` range and checks Z3 satisfiability for constraints, comparing the user's Lagrangian multiplier $\lambda$ against both the theoretical worst-case bound $\Delta E_{\text{QUBO}} / \Delta P_{\min}$ and the evaluated feasible vs. infeasible energy separation.
4. **Threading & Export**:
   - Evaluation runs in a `QThread` while the left panel displays a `QPainter`-based `LoadingSpinner`.
   - On completion, the left panel switches to a scrollable statistics view and the right panel reveals the `Download Project (.zip)` button (`project_QUBO-<date>.zip` containing `energies.csv`, `energy_landscape.png`, `connectivity_graph.png`, and `metadata.json`).
